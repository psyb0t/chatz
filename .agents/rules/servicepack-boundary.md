# Servicepack boundary

chatz is built on [servicepack](https://github.com/psyb0t/servicepack). `make servicepack-update` syncs the framework's files over this tree, so an edit to a framework-owned file is lost on the next update and can break the framework contract. If one of them needs to change, raise it with the owner instead of editing it.

## Framework-owned, never edit

- `cmd/main.go`, `cmd/main_test.go`
- `internal/app/` and `internal/pkg/service-manager/` (the framework's app wrapper and service runner, not chatz code)
- `pkg/runner/`
- `Makefile.servicepack`, `Dockerfile.servicepack`, `Dockerfile.servicepack.dev`, `pre-commit.sh`
- `scripts/make/servicepack/`
- `.gitattributes`, `.github/workflows/collaborators-only.yml`, `.github/workflows/issue-pull.yml`, `.github/workflows/mirror-and-archive.yml`
- `servicepack.version`, written by the updater

`internal/pkg/services/services.gen.go` is generated by `make service-registration`. Never edit it by hand.

The sync excludes are the floor in `scripts/make/servicepack/do_update.sh` (`EXCLUDE_ARGS`) plus every line of `.servicepackupdateignore`. When unsure whether a file is framework-owned, check both and the servicepack repository: if servicepack ships the file and neither list excludes it, the framework owns it.

## Project-owned, safe to edit

- `Makefile`, `Dockerfile`, `Dockerfile.dev`, `docs/`, `tests/`, `README.md`, `CHANGELOG.md`, `.gitignore`: excluded by the updater's floor.
- `cmd/init.go`, `cmd/commands.go`, `.golangci.yml`, `.dockerignore`, `.gitleaks.toml`, `.github/dependabot.yml`, `.github/workflows/pipeline.yml`, `.github/FUNDING.yml`, the `issue-pull` and `mirror-and-archive` workflows, `.agents`: listed in `.servicepackupdateignore`.
- `internal/pkg/services/` except `services.gen.go`.
- Everything chatz added: `api/`, `web/`, `internal/pkg/http/`, `internal/pkg/core/`, `internal/pkg/mcp/`, `internal/pkg/db/`, `internal/pkg/upstreams/`, `internal/pkg/secrets/`, `internal/pkg/logging/` and the other app packages.

## Customizing framework steps

- Override a framework Make script by adding `scripts/make/<name>.sh`. `find_script_path` in `Makefile.servicepack` prefers it over `scripts/make/servicepack/<name>.sh`. The overrides here run their commands in the dev container through `scripts/make/lib/dev.sh`.
- Override a framework target by defining the same target in `Makefile`, which includes `Makefile.servicepack`.
- `go.mod` and `go.sum` are merged by the updater, not replaced.
