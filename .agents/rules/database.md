# Database

- chatz supports Postgres (default) and SQLite, chosen by `CHATZ_DB_DRIVER`. Every schema change must work on both.
- Migrations are embedded SQL in `internal/pkg/db/migrations/` (Postgres) and `internal/pkg/db/migrations/sqlite/` (SQLite, starting from the `0000014_initial_schema` baseline). A new migration adds an `up` and `down` file with the same number under both directories. Postgres history is never replayed on SQLite.
- Migrations run on every startup inside `db.Connect`, and `migrate` (`make migrate`) runs them and exits. Never edit a migration that has shipped; add a new one.
- Models are in `internal/pkg/db/models/`. Repositories in `internal/pkg/db/repositories/*.gen.go` are generated by `cmd/repogen` (`make generate-repos` or `make generate`). Change the model or the generator, never the output.
- Chats are soft-deleted through gorm's `DeletedAt`. Queries go through the generated repositories so the soft-delete filter applies.
- The SQLite file must sit directly under `/data` and the pool is one connection with WAL mode (`internal/pkg/db/sqlite.go`). Do not add a code path that needs concurrent SQLite writers.
- Integration tests use the same `db.Connect` path as production through `tests/testinfra`, so test setup cannot drift from the real schema.
